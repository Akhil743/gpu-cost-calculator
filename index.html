API token costs

For each model, a request costs:

fresh input × input price + cached input × cached price + output × output price

Batched requests use each provider's batch prices (half the standard rate). Cache writes are ignored: with a reused prefix they are a small one-off. Prompts above a model's long-context threshold switch to its long-context prices where the provider publishes them. A month is 30 days.

Self-hosting an open-weights model

Generating tokens is usually limited by memory bandwidth, not compute: every step reads the weights and every sequence's KV cache. So one decode step takes the longer of

(weights read + sequences × KV cache per sequence) ÷ (bandwidth × efficiency) 2 × active parameters × sequences ÷ (peak FLOPS × utilisation)
  • KV cache per token = 2 × layers × KV heads × head size × bytes, from each model's published config.
  • Mixture-of-experts models read only the experts a batch touches: a share of 1 − (1 − active/total)batch of the weights.
  • Prompt processing (prefill) is compute-bound: 2 × active parameters FLOPs per prompt token, at 50% utilisation.
  • Bandwidth efficiency 70%, decode compute utilisation 40%, and 85% scaling per extra GPU in a replica.
  • A replica is the fewest of 1, 2, 4 or 8 GPUs that hold the weights plus 8 sequences of cache, using 90% of memory.
  • Cost per request = replica cost per second × seconds of replica time per request ÷ average utilisation.
  • Self-hosting is billed in whole replicas with at least one always on, so it only wins above a break-even volume.

These are first-order estimates. Real serving stacks (vLLM, TensorRT-LLM, SGLang) add continuous batching, speculative decoding and prefix caching, so treat the result as a range and measure your own workload before committing.

Memory and training

Serving memory = weights (parameters × bytes per parameter) + KV cache (per token × context × sequences).

Training compute uses the standard rule of thumb from scaling-law research:

FLOPs = 6 × active parameters × training tokens GPU-hours = FLOPs ÷ (peak BF16 FLOPS × MFU) ÷ 3600

Calibration: Llama 3.1 405B trained on 15.6T tokens. At 35% MFU on H100s this gives 30.4M GPU-hours; Meta reported 30.84M. Smaller models use GPUs less efficiently: Meta's figures for the 8B and 70B imply roughly 14% and 25%. Mixed-precision Adam needs about 16 bytes per parameter before activations, which sets the minimum number of GPUs even with full sharding.
